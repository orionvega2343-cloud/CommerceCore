# Order

**Order** - пользовательский заказ, собирает внутри себя все выбранные товары из корзины пользователя и предлагает оплату товара

## Доменная модель

Доменная модель заказа Order представляет структуру данных с набором полей:

    Id - уникальный идентификатор заказа
    UserId - идентификатор пользователя, которому принадлежит заказ
    CartId - идентификатор корзины, из которой оформлен заказ
    Status - статус заказа: "created", "paid", "shipped", "cancelled", "completed"
    TotalAmount - общая сумма заказа, посчитанная на момент оформления
    CreatedAt - дата создания заказа
    UpdatedAt - дата обновления заказа

Доменная модель позиции в заказе OrderItem представляет структуру данных с набором полей:

    Id - уникальный идентификатор позиции
    OrderId - идентификатор заказа, к которому относится позиция
    ProductId - идентификатор товара из каталога
    Quantity - количество товара в позиции
    PricePerUnit - цена товара за единицу, зафиксированная на момент оформления заказа

## Правила

У доменной модели Order есть бизнес-правило смены статуса:

```TransitionStatus(next)``` - проверяет и совершает переход между статусами по жёсткой схеме:
- ```created``` → ```paid``` или ```cancelled```
- ```paid``` → ```shipped``` или ```cancelled```
- ```shipped``` → ```completed```

Любой другой переход возвращает ошибку ```UnknownStatus```.

## Методы OrderRepo

1. CreateOrder - создает заказ
2. CreateOrderItem - создает позицию в заказе
3. GetOrderById - находит заказ по идентификатору
4. GetOrderItems - получает позиции заказа (все позиции конкретного заказа)
5. ListAllOrders - получение заказов всех пользователей, доступно только для роли Admin
6. ListOrderByUserId - получение заказов конкретного пользователя (по userId)
7. UpdateStatus - обновляет статус заказа по id

## Checkout

Cоздание заказа - только через бизнес-метод Checkout, отдельной прямой ручки такой как CreateOrder - нет
Работает он, так:
1. Совершается попытка получения пользовательской корзины (CreateOrGet)
2. Подгружаем позиции корзины (LoadItems)
3. Присваиваем загруженные позиции в cart.Items
4. Доменный бизнес-метод Checkout - проверяет, что статус active и не пустой
5. Итерируемся в цикле по позициям в корзине, и высчитываем их общую стоимость, сохраняя ее в переменную-накопитель
6. Собираем новую модель order, с уже заполненными данными
7. Открываем транзакцию
8. Создаем заказ (CreateOrder)
9. В цикле по каждой позиции корзины создаем OrderItem (ProductId, Quantity, PricePerUnit = PriceSnapshot из корзины) и сохраняем его через CreateOrderItem
10. Метод DecrementStock - списывает остаток товара, в случае недостаточного остатка выбрасывается ошибка и случается откат транзакции
11. SetStatus - сохраняет новый статус корзины (выставленный доменным Checkout на шаге 4) в БД
12. Транзакция коммитится
13. Публикуем событие order.created в Kafka - ПОСЛЕ успешного коммита, вне SQL-транзакции: Kafka не участник транзакции, сбой публикации не должен откатывать уже успешно оформленный заказ - ошибка только логируется

## TransitionStatus(order)
Переход статуса заказа:
1. Получаем заказ по идентификатору
2. Проверяем права: не-админ может только отменить (next == "cancelled") свой собственный заказ (order.UserId == userId) - любой другой переход или чужой заказ для не-админа запрещён (ErrForbidden). Админ может переводить в любой статус любой заказ (в рамках схемы переходов)
3. Вызываем доменный метод order.TransitionStatus для проверки и перехода статусов
4. Обновляем статус через SQL (UpdateStatus)
