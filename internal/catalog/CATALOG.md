## Catalog - каталог товаров, полный CRUDL по домену

## Product
Доменная модель продукта, имеет поля
```
    id - уникальный номер(генерируется внутри БД)
    name - название товара
    price - цена товара
    stock_quantity - количество товара
    is_active - булево значение для мягкого удаления товара
```
---
   
## Правила
У доменной модели Product есть 2 бизнес правила:
1. ```Deactivate() - обеспечивает смену состояния, для мягкого удаления товара```
2. ```Validate() - валидирует поля, name, price StockQuantity```
---


## DTO(Data Transfer Object)
DTO - позволяет обработчикам общаться с бизнес-логикой приложения, не раскрывая наружу доменную модель
1. ```ProductRequest``` - данные, пришедшие от пользователя, хендлер конвертирует их в ```domain.Product``` и передаёт в сервис
2. ```ProductResponse``` - доменная модель ```domain.Product```, сконвертированная хендлером обратно в DTO для ответа клиенту
3. ```ProductListResponse``` - обёртка над срезом ```ProductResponse```, используется в ответе ```GetAllProducts```

## Cache aside
Catalog - имеет 2 источника данных для товаров
1. ```PostgresRepo``` (реализует ```domain.ProductRepo```) - отправляет SQL запросы напрямую в БД, для получения нужных данных
2. ```RedisRepo``` (реализует ```domain.ProductCache```) - это только клиент кэша: умеет получить/записать/удалить товар или список товаров в Redis, сам по себе паттерн cache-aside не реализует

Паттерн Cache aside реализован в **сервисном слое** (```ProductServiceImpl```, методы ```GetProductById``` и ```GetAllProducts```): сначала сервис пытается получить данные из кэша, и только при промахе идёт в ```PostgresRepo```, после чего записывает полученный результат обратно в кэш. Это нужно для избежания высокой нагрузки на сервер, например: 100 администраторов, каждый хочет получить товар либо по id, либо получить список всех товаров - это значит, что все 100 запросов полетят именно в БД, дает очень сильную нагрузку на сервер, для этого используется cache aside, он определяет если в кэше нет актуальных данных, он делает запрос к БД, и записывает их в КЭШ и при повторном запросе отдает данные уже из кэша
